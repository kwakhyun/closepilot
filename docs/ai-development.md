# AI를 활용한 개발 절차

이 프로젝트는 Codex를 활용해 제품 범위를 정하고 도메인 코드, UI, 테스트, 배포 설정, 문서를 작성했다. 생성된 코드는 테스트와 독립 재계산으로 확인했으며, 변경할 때 지켜야 할 기준을 저장소에 남겼다.

## 저장소에 포함한 개발 도구와 지침

| 자산                             | 역할                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------- |
| `AGENTS.md`                      | 도메인 규칙, 보안, 구현·검증 범위의 정확한 설명, 검증 순서에 관한 공통 지침      |
| `CLAUDE.md`                      | 공통 지침을 참조해 에이전트별로 같은 내용을 중복 관리하지 않도록 함              |
| `scripts/check-architecture.mjs` | TypeScript AST에서 import 경계와 클라이언트의 서버 의존성 검사                   |
| `.githooks/pre-commit`           | 커밋 전 레이어·타입·도메인/DB 테스트 실행                                        |
| `.github/workflows/verify.yml`   | PR 생성·변경 또는 push 시 빌드, PostgreSQL 테스트, HTTP 흐름, Kotlin 재계산 실행 |
| `fixtures/closed-package.json`   | 고정된 입력과 시각으로 재생성할 수 있는 기준 마감 증빙                           |

`git config core.hooksPath .githooks`로 커밋 훅을 활성화한다. 로컬 훅만으로 검토를 대신할 수는 없으므로 CI 결과와 코드 리뷰를 함께 확인한다.

## 구체적인 변경 예: 수수료 정책

먼저 변경된 계약 조건을 확인하고 반올림 경계값과 부분 환불을 포함한 반례를 작성한다. TypeScript와 Kotlin을 각각 수정한 뒤 규칙 버전을 올린다. 고정 검증 데이터를 다시 생성해 행별 차이가 의도한 결과인지 확인한다. 화면의 수수료율 설명과 운영 문서도 함께 갱신한다.

계약 근거 없이 계산 규칙을 바꾸거나 테스트를 통과시키려고 예상값만 바꾸지 않는다. 정확성은 명시된 입력, 반드시 유지해야 할 규칙(불변식), 독립 재계산 결과로 확인한다.

## 구현 중 발견하고 수정한 문제

- 로컬 PGlite의 부모 디렉터리가 없으면 DB 초기화가 실패했다. 부모 디렉터리를 명시적으로 생성했다.
- Next.js 내부 URL과 브라우저가 접속한 호스트가 달라 정상 POST 요청이 Origin 검사에서 거부됐다. Host와 명시적 `APP_ORIGIN` 설정을 구분하고 HTTP 회귀 테스트를 추가했다.
- 500 오류의 응답 본문과 헤더에 서로 다른 `requestId`가 들어가 로그를 찾기 어려웠다. 본문·헤더·로그에서 같은 ID를 사용하도록 수정하고 비밀값이 노출되지 않는지 검사했다.
- Windows의 한글 경로에서 Kotlin 테스트 classpath가 깨졌다. CLI 스크립트에서 빌드 출력만 ASCII 임시 경로로 분리했다. 동일한 테스트와 재계산을 다시 실행했다.

- 공개 PostgreSQL 검증에서 JSON 문자열을 드라이버가 다시 직렬화하는 문제를 발견했다. PGlite는 이미 직렬화된 문자열도 허용해 로컬 테스트만으로는 드러나지 않았다. JavaScript 객체를 드라이버에 전달하도록 수정하고 JSON 객체 형식과 필수 필드를 검사하는 DB 제약을 추가했다. 마이그레이션과 회귀 테스트 2개를 추가한 뒤 공개 API 검증 20단계를 다시 통과했다.

- 첫 Vercel 배포에서 Next.js 16.3의 standalone 출력과 배포 어댑터를 함께 사용할 때 추적 파일을 찾지 못했다. 패키지 코드와 [같은 문제의 재현 이슈](https://github.com/vercel/next.js/issues/96646)를 확인해 배포 대상에 따라 `output` 설정을 분리했다.
- 문구 검토 중 대사 결과의 설명이 기존 검토 기록의 fingerprint에 포함된다는 점을 확인했다. 표시용 문구를 별도로 구성해 계산 결과와 기존 승인·증빙은 유지하면서 표현만 바꿀 수 있도록 했다.

## 제품의 AI 기능과 구분

공개 앱은 LLM API를 호출하지 않는다. 검토 가이드는 대사 결과와 정해진 설명, 원본 자료 ID를 보여준다. 개발 과정에서 Codex를 사용한 것과 제품에 AI 기능을 탑재한 것은 구분한다. 채팅이나 LLM 에이전트 기능은 구현하지 않았다.

향후 LLM 설명 기능을 추가한다면 대사 결과와 필요한 증빙 참조 정보만 읽도록 제한한다. 응답은 JSON 스키마로 검증하고, 답변에 포함된 자료 ID가 실제로 존재하는지 확인한다. 호출 시간과 비용에 한도를 두고 개인정보 전달을 최소화하며, 실패하면 기존 규칙 기반 안내를 표시한다. 금액 계산·원본 수정·승인·마감·송금 도구는 설명 에이전트에 제공하지 않는다. API 키, 예산, 데이터 처리 정책을 정하고 별도로 평가해야 하며, 이는 **설계 제안으로 현재 구현된 기능은 아니다.**
