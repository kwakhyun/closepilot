# 공개 데모의 보안 모델

실제 고객 자료를 취급하도록 승인된 시스템이 아니다. 지원서 검토자가 합성 데이터로 전체 흐름을 체험하는 공개 샌드박스다.

| 위협                         | 구현한 통제                                                                              | 남는 한계                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 다른 방문자의 상태 읽기/쓰기 | 32바이트 랜덤 HttpOnly 세션 토큰, DB에는 SHA-256만 저장, 세션별 WHERE 조건               | 사용자 계정/조직/RBAC가 아니다. 토큰 탈취 시 해당 세션 접근 가능    |
| 교차 사이트 변경             | SameSite=Lax, POST Origin/Host 및 Sec-Fetch-Site 검사                                    | 브라우저 외 클라이언트의 세션 생성을 인증하는 장치는 아님           |
| 중복/동시 명령               | 행 잠금, 버전 검사, 요청 키 유일성, 원자적 receipt                                       | 세션 쓰기가 직렬화됨. 분산 장기 작업 큐 없음                        |
| CSV 수식/잘못된 숫자         | 엄격한 금액·날짜 파싱, 내보내기 수식 접두어 무력화                                       | 허용된 ID/메모에 사용자가 개인정보를 직접 넣는 일까지 판별하지 않음 |
| 마감 후 수정                 | application 검사, DB UPDATE 거부 트리거                                                  | DB 관리자에게서 보호하는 불변 저장소가 아님                         |
| 감사 기록 일부 수정          | 이전 해시 포함 체인, UPDATE 거부, Kotlin 검증                                            | 전체 체인 재작성/외부 기준 없는 절단 탐지에 제한. 서명 아님         |
| 공개 자원 남용               | 파일 256KB·500행, 총 주문500/정산1000, 파일12, 이벤트100, 세션 생성 IP/시간10·전역/일250 | WAF/Bot 검증 없음. 반복 읽기/미리보기의 완전한 비용 상한은 아님     |
| 오류/키 노출                 | 비공개 env, JSON 오류에는 안전한 코드/메시지/요청ID, 로그에 예외 타입만                  | 운영자는 Vercel/DB 권한과 로그 보관을 별도로 관리해야 함            |

## 데이터 수명

발급 후 6시간에 API 접근이 만료된다. 다음 세션 생성 트랜잭션이 만료된 workspace와 종속 receipt/audit를 삭제한다. 트래픽이 없으면 물리 데이터가 더 오래 남을 수 있다. 초기화 버튼은 새 세션을 발급하며 이전 데이터를 즉시 삭제하지 않는다. 정확한 삭제 SLA, WORM 보관, 법정 보존 의무는 구현하지 않았다.

알 수 없는 CSV 열은 표준화 결과에 보존하지 않는다. 원본 CSV 파일은 영구 저장하지 않고 표준 필드와 digest만 저장한다. 주문 ID/메모에도 개인정보를 넣을 수 있으므로 **개인정보 자동 제거 기능이 있다고 주장하지 않는다.**

## 응답과 플랫폼 경계

상태 API는 `Cache-Control: no-store, private`를 사용한다. 프로덕션 쿠키는 Secure, HttpOnly, SameSite=Lax다. CSP, frame 차단, nosniff, Referrer/Permissions 정책을 설정한다. 현재 CSP는 Next의 인라인 부트스트랩을 위해 `unsafe-inline`을 허용한다. nonce 기반 CSP까지 강화한 구현은 아니다. 프로덕션에 `unsafe-eval`은 허용하지 않는다.

DB 연결 문자열·Vercel 토큰은 `.env*`/플랫폼 변수에만 저장하고 git에서 제외한다. `.env.example`에는 비밀이 없다. 테스트 DB URL은 CI에서만 사용하는 공개 임시 비밀번호이며 운영 비밀번호가 아니다.

## 실사용 전 필수 조건

실제 고객/법무/보안 담당자와 데이터 처리·보관 정책을 확인하고, SSO/RBAC와 조직 경계, 작성자·승인자 분리, 원본 자료의 서명/보관, 감사 권한 분리, WAF/작업 큐/모니터링/복구 시험을 도입해야 한다. 실제 결제·회계 판단은 담당자와 원천 시스템의 검증을 거쳐야 한다.
