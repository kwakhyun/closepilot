# 공개 데모의 보안 모델

방문자가 가상 거래로 전체 작업 과정을 체험하는 공개 데모다. 실제 고객 자료를 처리하는 운영 시스템으로 사용해서는 안 된다.

| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 다른 방문자의 자료 조회·수정   | 32바이트 난수 세션 토큰과 HttpOnly 쿠키 사용, DB에는 토큰의 SHA-256 해시만 저장, 세션별 조회 조건 적용                          | 사용자 계정·조직별 권한 관리 기능은 아니다. 토큰이 탈취되면 해당 세션에 접근할 수 있다.                     |
| 다른 사이트에서 보낸 변경 요청 | SameSite=Lax, POST의 Origin·Host·Sec-Fetch-Site 검사                                                                            | 브라우저 외부에서 세션을 만드는 클라이언트의 신원을 인증하지는 않는다.                                      |

## 데이터 수명

AI 생성 시도는 PostgreSQL에서 UTC 기준 세션당 시간별 10회, 전체 일별 100회로 제한하며 동시 실행은 세션당 1건, 전체 4건이다. 동일 근거와 모델의 성공한 초안은 세션 안에서만 재사용한다. 차단된 요청은 실제 모델을 호출하지 않고 규칙 기반 초안으로 전환한다. 생성 횟수와 실행 예약에 대한 제한이며, 공급자의 실제 청구 금액을 고정하는 예산 기능이나 전체 조회 요청에 대한 봇 차단은 아니다.

AI 캐시와 실행 예약은 작업공간 삭제 시 외래 키로 함께 삭제한다. 실패한 실행 예약은 해제하며 정리에 실패해도 45초 뒤 만료된다. 캐시를 읽을 때도 현재 세션과 버전, 마감 상태, 미검토 대상과 인용 근거를 다시 확인한다. HTTP 응답의 `no-store` 정책과 서버 내부의 세션별 캐시는 별개의 통제다.

작업 접근 권한은 생성 또는 복귀 후 6시간에 만료된다. 별도 HttpOnly 보관함 쿠키는 최대 30일이며, 이를 가진 브라우저에서 작업별 생성일로부터 30일간 최대 12개를 다시 열 수 있다. 이 쿠키 역시 bearer capability이므로 탈취되면 보관함 접근이 가능하다. 계정 인증, 기기 간 복구나 기업 권한을 제공하지 않는다. 쿠키 삭제 후에는 자료 복구 수단이 없다. 보관함 UUID만으로는 접근할 수 없고 서버가 소유 해시를 함께 검사한다.

다음 작업을 생성하는 트랜잭션에서 보관 기간이 지난 작업과 연결된 요청 이력, 감사, 보관함, 접근 권한과 AI 캐시를 삭제한다. 이후 접속이 없으면 DB에 더 오래 남을 수 있다. 기존 버전의 6시간 작업은 보관함에 자동 추가하거나 수명을 연장하지 않는다. **새 데모 시작**은 이전 자료를 즉시 삭제하지 않는다. 정시 삭제, 영구 보관, WORM이나 법정 보존을 보장하지 않는다.

연결하지 않은 CSV 열은 저장하지 않는다. 원본 파일 자체를 보관하는 대신 표준 필드와 내용 체크섬(`digest`)을 저장한다. 주문번호나 메모에도 개인정보가 들어갈 수 있으므로 **개인정보를 자동으로 제거하는 기능은 제공하지 않는다.**

## 응답과 플랫폼 경계

검토 임시 메모는 서버의 AI 초안 캐시와 다르다. 현재 탭의 `sessionStorage`에 메모, 증빙 참조, 결과 fingerprint와 만료 시각만 저장한다. 인증 쿠키는 저장하지 않으며 새로 저장한 시점부터 최대 6시간, 작업 생성 후 최대 30일까지 복원할 수 있다. 기존 메모의 만료 시각은 유지한다. 만료 데이터 정리는 저장소를 읽거나 메모를 저장할 때 수행하므로 정시 삭제를 보장하지 않는다. 브라우저 저장소 차단과 용량 오류는 사용자에게 알리고 서버 승인으로 대체하지 않는다.

증빙 검사와 정책 비교 API에도 유효한 세션과 동일 출처 Origin이 필요하다. 증빙 검사 요청의 한도는 5,000,000바이트로 CSV의 256,000바이트 한도와 구분한다. 업로드한 패키지는 서버에 보관하지 않으며 화면에는 최대 12개를 메모리로 유지한다. 해시를 다시 계산해 만든 위조 파일의 진위를 보증하지 않는다. 파일의 체크섬, 계산과 감사 연결이 일관적인지 검사하는 기능이다.

작업 상태 API에는 `Cache-Control: no-store, private`를 적용한다. 공개 배포의 쿠키에는 `Secure`, `HttpOnly`, `SameSite=Lax`를 설정한다. CSP, 외부 프레임 삽입 차단, `nosniff`, Referrer-Policy, Permissions-Policy도 적용한다. 현재 CSP는 Next.js의 초기 실행 스크립트를 위해 `unsafe-inline`을 허용하며 nonce 방식까지 적용하지는 않았다. 프로덕션에서는 `unsafe-eval`을 허용하지 않는다.

DB 연결 문자열과 Vercel 토큰은 로컬 환경 설정 또는 플랫폼의 비밀값 저장소에서 관리하고 Git에 포함하지 않는다. `.env.example`에는 비밀값이 없다. CI의 DB URL에는 임시 테스트 DB용 비밀번호만 포함하며 운영 DB 비밀번호는 사용하지 않는다.

## 실사용 전 필수 조건

실제 고객과 법무 및 보안 담당자에게 데이터 처리와 보관 정책을 확인해야 한다. 기업 로그인(SSO), 역할별 권한(RBAC), 조직별 데이터 분리, 작성자와 승인자 분리, 원본 자료의 서명과 보관, 감사 권한 분리도 필요하다. WAF, 작업 큐, 모니터링, 복구 시험을 포함한 운영 체계를 별도로 마련해야 하며, 실제 결제나 회계 판단은 담당자와 원천 시스템의 검증을 거쳐야 한다.
