# ADR 0001 — TypeScript 공개 웹과 Kotlin 대사 서비스 경계

상태: 채택 · 2026-08-31 · Kotlin 대사 경계 확장 2026-09-01

## 맥락

지원 직무는 Kotlin 중심의 도메인 주도 설계(DDD), 고객 문제 해결, REST·PostgreSQL, AI를 활용한 개발 역량을 요구한다. 이 포트폴리오에서는 검토자가 별도 설치 없이 전체 작업 과정을 체험하고 설계와 테스트 근거를 확인할 수 있도록 하는 데 우선순위를 두었다.

## 선택

웹 화면과 공개 REST API는 Next.js·TypeScript로 구현해 Vercel에 배포하고 PostgreSQL에 연결한다. Kotlin/JVM 모듈은 버전형 요율 정책과 주문·정산 입력을 받는 `POST /reconcile` 대사 유스케이스, 내보낸 마감 증빙을 확인하는 CLI·`POST /verify`를 제공한다. 로컬·CI에서는 Kotlin HTTP 경계를 실제로 실행하지만 공개 Vercel 환경은 JVM을 호스팅하지 않아 TypeScript 인프로세스 엔진을 사용한다. 두 런타임의 역할을 문서와 화면에 구분한다. AI는 검토 메모 초안에만 사용하며 서버가 만든 근거 목록 밖으로 나갈 수 없게 제한한다.

## 고려한 대안

| 대안                                         | 이 범위에서의 판단                                                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Kotlin Spring 공개 서버 + Next.js 프런트엔드 | 채용 공고의 서버 구성에 더 가깝지만 별도 호스팅·인증·TLS·운영이 필요하다. 이번 범위에서는 JDK HTTP 경계와 OpenAPI 계약을 먼저 구현한다. |
| 브라우저에서만 계산                          | 배포는 쉽지만 서버의 세션 분리, 동시 요청 처리, DB의 마감 잠금을 구현할 수 없어 선택하지 않았다.                                        |
| 여러 서비스와 Kubernetes 운영                | 현재 데모의 데이터와 예상 사용량에 비해 운영 부담과 장애 가능 지점이 늘어나므로 도입하지 않았다.                                        |
| LLM을 이용한 자동 승인                       | 금융 판단을 모델에 맡기는 위험이 있어 채택하지 않았다. 읽기 전용 근거 도구를 사용하는 선택형 메모 초안만 제공한다.                      |

## 기대 효과와 유지보수 부담

하나의 공개 앱과 DB로 전체 과정을 운영하면서 Kotlin의 핵심 대사 계약을 별도로 실행·평가할 수 있다. 검증 CLI는 필요한 의존성을 설치한 뒤에는 네트워크 연결 없이 마감 증빙을 검사하고, 로컬 REST 경계는 외부 서비스 없이 같은 도메인 함수를 호출한다. 다만 두 언어에 계산 규칙이 존재하므로 고정 검증 데이터, 프로필 요율, 독립적인 반례 테스트, 규칙 버전과 OpenAPI 계약으로 차이를 관리해야 한다. 로컬 전용 JDK HTTP 서버는 인증·TLS·수평 확장을 갖춘 운영 서버가 아니다.

Kotlin을 공개 운영 서비스로 확장한다면 현재 `/reconcile` 유스케이스를 기준으로 명령 처리, 인증, 저장소 경계를 단계적으로 이관한다. 그 전에 실제 고객의 계약 조건, 접근 권한, 원본 데이터, 보관 정책과 서비스 간 장애 처리 기준을 합의해야 한다.
