# ADR 0001 — 작은 웹 런타임과 독립 Kotlin 검증기

상태: 채택 · 2026-08-31

## 맥락

채용 포지션은 Kotlin 중심의 DDD, 고객 문제 해결, REST/PostgreSQL, AI를 활용한 개발을 요구한다. 이 포트폴리오의 중요한 결과는 검토자가 설치 없이 완결된 작업을 체험하고 설계·테스트 근거를 확인하는 것이다.

## 선택

웹/UI/REST는 Next.js/TypeScript로 Vercel에 배포하고 PostgreSQL을 연결한다. 별도 Kotlin/JVM CLI가 내보낸 마감 패키지를 독립 재계산한다. Kotlin을 사용했다는 이유만으로 웹 백엔드가 Kotlin이라고 표시하지 않는다.

## 고려한 대안

| 대안                             | 이 범위에서의 판단                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Kotlin Spring 서버 + Next 프런트 | 직무의 서버 스택에는 더 가깝지만 별도 호스팅·인증·운영을 늘린다. 필요하면 application 계약을 Kotlin 서비스로 이관할 수 있다. |
| 브라우저만으로 계산              | 배포는 쉽지만 세션 격리·동시성·DB 마감 잠금을 증명하지 못한다. 제외했다.                                                     |
| 거대한 다중 서비스/Kubernetes    | 현 단계의 작은 데이터와 트래픽에 비해 운영 비용과 실패 지점이 크다. 구현했다고 주장하지 않는다.                              |
| 실제 LLM 자율 승인               | 금융 판단 위험과 유료 API 의존성이 생긴다. 공개 데모에서는 결정적 가이드를 사용한다.                                         |

## 결과와 비용

하나의 공개 앱과 무료 DB로 전체 흐름을 운영할 수 있다. 검증기는 네트워크 없이 내려받은 패키지를 검사한다. 대신 계산 규칙이 두 언어에 존재하므로 골든 패키지, 독립 반례 테스트, 규칙 버전으로 차이를 관리해야 한다. 데모 검증을 위해 택한 이 중복을 모든 운영 서비스에 권장하지 않는다.

실서비스의 첫 Kotlin 전환 대상은 UI가 아니라 현재의 명령/대사 application 경계다. 그 전에는 실제 고객 계약, 권한, 원천 데이터와 보관 정책부터 합의해야 한다.
