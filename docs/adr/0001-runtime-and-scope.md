# ADR 0001 — TypeScript 웹 서비스와 Kotlin 독립 검증기

상태: 채택 · 2026-08-31

## 맥락

지원 직무는 Kotlin 중심의 도메인 주도 설계(DDD), 고객 문제 해결, REST·PostgreSQL, AI를 활용한 개발 역량을 요구한다. 이 포트폴리오에서는 검토자가 별도 설치 없이 전체 작업 과정을 체험하고 설계와 테스트 근거를 확인할 수 있도록 하는 데 우선순위를 두었다.

## 선택

웹 화면과 REST API는 Next.js·TypeScript로 구현해 Vercel에 배포하고 PostgreSQL에 연결한다. Kotlin/JVM 검증기는 내보낸 마감 증빙을 CLI와 로컬 전용 REST 경계로 받아 독립적으로 재계산한다. 웹 백엔드와 Kotlin 검증기의 역할을 문서와 화면에서 구분한다. AI는 검토 메모 초안에만 사용하며 서버가 만든 근거 목록 밖으로 나갈 수 없게 제한한다.

## 고려한 대안

| 대안                                    | 이 범위에서의 판단                                                                                                                            |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Kotlin Spring 서버 + Next.js 프런트엔드 | 채용 공고의 서버 구성에 더 가깝지만 별도 호스팅·인증·운영이 필요하다. 향후 application 계층을 Kotlin 서비스로 옮길 수 있도록 경계를 유지한다. |
| 브라우저에서만 계산                     | 배포는 쉽지만 서버의 세션 분리, 동시 요청 처리, DB의 마감 잠금을 구현할 수 없어 선택하지 않았다.                                              |
| 여러 서비스와 Kubernetes 운영           | 현재 데모의 데이터와 예상 사용량에 비해 운영 부담과 장애 가능 지점이 늘어나므로 도입하지 않았다.                                              |
| LLM을 이용한 자동 승인                  | 금융 판단을 모델에 맡기는 위험이 있어 채택하지 않았다. 읽기 전용 근거 도구를 사용하는 선택형 메모 초안만 제공한다.                            |

## 기대 효과와 유지보수 부담

하나의 공개 앱과 DB로 전체 과정을 운영할 수 있다. 검증기는 필요한 의존성을 설치한 뒤에는 네트워크 연결 없이 내려받은 증빙 파일을 검사한다. 로컬 REST 경계도 외부 서비스 없이 같은 검증 함수를 호출한다. 다만 두 언어에 계산 규칙이 존재하므로 고정 검증 데이터, 독립적인 반례 테스트, 규칙 버전으로 차이를 관리해야 한다. 독립 검증을 위해 선택한 구조이며 모든 운영 서비스에 그대로 적용할 방식은 아니다.

Kotlin 서버로 확장한다면 명령 처리와 대사를 담당하는 application 계층부터 이관한다. 그 전에 실제 고객의 계약 조건, 접근 권한, 원본 데이터, 보관 정책을 합의해야 한다.
