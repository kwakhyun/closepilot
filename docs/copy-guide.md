# 용어와 문구 기준

화면은 재무 담당자가 다음 작업을 이해할 수 있도록 쓰고, 설계 문서는 개발자가 실제 동작과 한계를 확인할 수 있도록 쓴다. 같은 기능이나 수치는 화면·오류 안내·README·시연 문서에서 같은 이름을 사용한다.

## 주요 용어

| 용어               | 이 프로젝트에서의 의미                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 대사               | 주문 자료와 정산 자료를 대조해 금액과 입금일 정보를 확인하는 작업                                                         |
| 주문 총액          | 환불액을 차감하기 전 주문 금액의 합계. 회계상 매출 인식을 확정한 수치는 아님                                              |
| 예상 정산액        | 주문 총액에서 환불액과 데모 수수료를 뺀 금액                                                                              |
| 자료상 정산액      | 정산 자료에 기록된 금액의 합계. 은행 계좌에서 확인한 입금액이 아님                                                        |
| 차액               | 자료상 정산액에서 예상 정산액을 뺀 값. 원본 금액과 함께 유지됨                                                            |
| 차액의 절댓값 합계 | 거래별 차액의 부호를 제외하고 더한 값. 순차액이나 실제 회수할 금액이 아님                                                 |
| 미검토 거래        | 예외로 분류되었지만 아직 검토를 승인하지 않은 거래                                                                        |
| 입금 확인 필요     | 자료에 입금일이 없거나 마감 기준일 이후로 기록된 거래                                                                     |
| 검토 승인          | 원본 자료를 확인하고 사유·증빙 참조 정보를 기록하는 작업. 금액 수정이나 지급 승인이 아님                                  |
| 증빙 참조 정보     | 정산 파일명, 문의 티켓 번호 등 검토 근거를 찾는 데 쓰는 텍스트. 증빙 파일 자체를 업로드하거나 진위를 확인하는 기능은 아님 |
| 마감 증빙 파일     | 원본 입력, 대사 결과, 검토 근거, 감사 기록과 체크섬을 담은 JSON 파일                                                      |

자동으로 일치한 거래는 **일치**, 사용자가 검토를 승인한 예외 거래는 **검토 완료**로 표시한다. 사이드바의 대사 처리율은 `(자동 일치 건수 + 검토 완료 건수) / 전체 대사 건수`다. 예외 거래만을 대상으로 한 검토율과 구분한다.

## 버튼과 작업 이름

- **자료 가져오기**: CSV를 선택하고 미리보기를 여는 진입점.
- **자료 반영**: 검증한 CSV 전체를 작업 자료에 저장하는 명령.
- **대사 실행**: 현재 주문·정산 자료를 다시 비교하는 명령.
- **확인할 거래 보기**: 미검토 예외 거래 목록으로 이동하는 대시보드의 기본 동작.
- **검토 예시 불러오기**: 가상의 사유와 증빙 참조 정보를 입력하는 기능. 확인란 체크와 승인은 자동으로 수행하지 않음.
- **기록하고 다음 거래 보기**: 현재 검토를 저장하고 다음 미검토 거래를 여는 명령. 다음 거래가 없으면 해당 예외 유형에 맞는 승인 이름을 사용함.
- **차이 검토 승인 / 이월 검토 승인 / 중복 확인 승인**: 각각 차이의 사유, 다음 달 이월 판단, 중복 여부를 기록하는 명령. 원본 행·금액·합계는 바꾸지 않음.
- **8월 마감 확정**: 마감 조건을 확인한 뒤 현재 결과를 확정하고 수정을 차단하는 명령.
- **마감 증빙 다운로드 (JSON)**: 확정한 결과를 파일로 저장하는 기능.

## 문장 작성 원칙

- 안내는 “확인했습니다”, “저장합니다”처럼 사실을 설명하고, 요청은 “확인하세요”, “다시 시도해 주세요”로 쓴다. 같은 화면에서 “했어요”와 “했습니다”를 섞지 않는다.
- 금액을 고치지 않는 기능을 “차이 해결”이나 “정산 완료”로 표현하지 않는다. 필요한 경우 “검토 완료” 또는 “마감 확정”을 사용한다.
- 개발 용어는 대상에 맞게 설명한다. 화면의 “열 연결”은 문서에서 처음 등장할 때 “열 연결(매핑)”로, 체크섬은 “내용 변경을 확인하는 값”으로 풀어 쓴다.
- 오류 안내는 확인된 사실과 다음 행동을 함께 쓴다. 처리 결과를 모르는 경우 “저장된 데이터는 바뀌지 않았다”고 단정하지 않는다.
- 숫자와 단위를 붙이되 앞뒤 문장은 띄어 쓴다. 예: “주문 128건”, “정산 내역 127행”, “원본 파일 4개”.
- 무료 플랜, 보관 기간, 검증 결과는 실제 확인한 범위만 설명한다. “영구 보관”, “실제 입금 확인”, “AI 자동 승인”처럼 구현하지 않은 기능을 암시하지 않는다. AI 기능은 저장된 합성 근거로 만드는 선택형 검토 메모 초안이라고 표현한다.

## 표시 문구와 증빙 원문의 구분

표시용 설명은 `src/domain/review-copy.ts`, 예외 이름은 `src/domain/model.ts`, CSV 항목명은 `src/domain/csv.ts`에서 관리한다. 화면과 검토 안내 API는 같은 표시용 설명을 사용한다.

v1 대사 결과의 `explanation`은 이미 검토 기록의 fingerprint와 마감 체크섬 계산에 포함되어 있다. 문구 교정으로 기존 승인이 무효화되지 않도록 해당 값, 감사 기록의 원문, 저장된 검토 메모는 수정하지 않는다. 감사 화면의 영문 처리 유형은 표시할 때만 한글로 바꾸며, 내보낸 증빙과 검증용 고정 데이터는 원문을 유지한다.

API 필드명, 오류 코드, CSV의 기계 처리용 열 이름, 외부 라이선스와 자동 생성 파일도 문장 교정 과정에서 변경하지 않는다. 화면이 바뀌면 시연 순서와 README의 화면 캡처를 함께 확인한다.
