기준일: 2026-08-31. 수치는 합성 데이터 검증 결과이며 실제 고객 성과가 아니다.

## 실행한 검사

| 경계               | 방법                           | 확인한 내용                                                               |
| ------------------ | ------------------------------ | ------------------------------------------------------------------------- |
| Domain/Application | Vitest                         | 원 단위 정수·반올림, CSV, 예외 7종, 검토 결과 해시, 마감 조건             |
| HTTP               | Vitest + 실행 중인 서버        | Origin, 요청 본문 크기, JSON 형식, 오류 응답·요청 ID, 세션                |
| Repository/DB      | 로컬 PGlite / CI PostgreSQL 17 | 행 잠금, 중복 요청, 동시 수정, 세션 분리, 트랜잭션 롤백, 수정 차단 트리거 |
| Web 전체 흐름      | `scripts/smoke-api.mjs`        | CSV 반영 → 재대사 → 검토 승인 → 마감 확정 → JSON·CSV 내보내기             |
| Kotlin/JVM         | JDK 21 + Gradle                | 원본 재계산, 검토 결과 해시, 감사 기록, 변조된 증빙 거부                  |

TypeScript 테스트는 77개, Kotlin 테스트는 6개다. HTTP smoke 검사는 하나의 시나리오를 20단계로 확인하며, 별도의 단위 테스트 20개를 뜻하지 않는다.

로컬 API 실행 기록은 [api-smoke-local.json](evidence/api-smoke-local.json)에 있다. 고정된 입력으로 만든 기준 마감 증빙은 [closed-package.json](../fixtures/closed-package.json), 기준 합계는 [baseline.json](../fixtures/baseline.json)을 참고한다.

## 실제 HTTP 흐름

세션 2개를 만들고 서로 다른 쿠키로 구분한다. 같은 요청 키로 재시도하는 경우, 같은 키에 다른 본문을 보내는 경우, 동시에 버전을 수정하는 경우를 검사한다. 정상·오류 CSV, 재대사 조건, 미검토 거래가 있을 때의 마감 차단, 마감 후 수정 차단과 내보내기도 확인한다. 샘플 CSV를 반영한 최종 결과는 전체 131건, 자동 일치 123건, 검토 승인 8건이다. 보고서에는 토큰을 포함하지 않는다.

## 브라우저와 공개 배포

공개 URL은 [closepilot-delta.vercel.app](https://closepilot-delta.vercel.app)이다. Vercel에 전용 Neon PostgreSQL을 연결했다. 공개 API 검증 20단계를 통과했으며 [실행 보고서](evidence/api-smoke-production.json)에 실행 시각과 결과를 기록했다. 최초 실행의 7,977ms는 검증 스크립트 전체의 소요 시간으로, API 응답 시간이나 처리량을 측정한 벤치마크가 아니다.

최초 공개 API 검사에서 내려받은 증빙은 Kotlin CLI에서도 **대사 결과 131행, 자동 일치 123건, 검토 승인 8건, 감사 이벤트 17건**으로 재계산을 통과했다. 체크섬은 `d8ba21a305cbd18f0bd4f3a461da8f68d248d03bfe527ff4236f6f35340491f0`이다. 이 임시 파일에는 가상 거래만 포함되어 있으며 공개 보고서와 별도로 로컬 `.data`에 보관했다.

브라우저에서 주문·정산 CSV 샘플의 열 연결, 미리보기, 반영을 확인했다. 재대사 전 마감 차단, 예외 거래 8건의 검토 승인, 마감 확정과 다운로드 링크도 확인했다. 실행한 UI 흐름의 최종 상태는 대사 결과 131행, 자동 일치 123건, 검토 승인 8건이며 원본 순차액 37,353원을 유지했다. 검토 가이드의 규칙 기반 표기, 차트의 채널별 전환, 표의 다음·이전 페이지도 확인했다.

좁은 화면에서는 표의 스크린 리더용 숨김 요소가 스크롤 영역 밖으로 나가 페이지 너비를 늘리는 문제를 발견했다. 표의 스크롤 영역을 위치 기준으로 지정해 수정했다. 너비 390px 화면에서 문서 너비가 375px(스크롤바 제외)로 유지되어 가로로 넘치지 않는 것을 확인했다. 제품 가이드도 같은 너비에서 검사했다. 화면 캡처는 `docs/evidence`에 저장한다.

## 문구 교정 후 재검증

2026-08-31, 화면·오류 안내·제품 가이드와 내부 문서를 [용어 기준](copy-guide.md)에 맞춰 교정했다. 계산 규칙, 저장 형식, API 필드명은 변경하지 않았다.

- `npm run verify`: 레이어 경계, 타입, lint, TypeScript 테스트 77개와 배포용 빌드 통과.
- `npm run fixtures` 후 `git diff --exit-code -- fixtures migrations`: 변경 없음. 기준 마감 파일의 체크섬도 유지됐다.
- Kotlin 테스트 6개와 기준 마감 파일의 독립 재계산 통과.
- 브라우저: CSV 열 중복 연결 오류와 재검증, 주문·정산 샘플 반영, 재대사 전 마감 차단, 예외 8건의 검토 승인, 마감 확정, 감사 기록 재검증을 확인했다. 완료 후에도 대사 결과 131행, 자동 일치 123건, 검토 승인 8건, 원본 순차액 37,353원을 유지했다.
- 교정 전에 만든 로컬 마감 세션과 공개 데모의 검토 승인도 유효하게 표시됐다. v1 증빙에 포함된 설명과 감사 원문은 보존하고, 화면에 표시할 때만 교정한 문구를 적용했다.
- 1440px 데스크톱과 390px 모바일에서 문구와 줄바꿈을 확인했다. 모바일 자료 가져오기 대화상자와 제품 가이드 모두 페이지 너비가 뷰포트를 넘지 않았다. 없는 페이지의 안내와 마감 후 읽기 전용 상태도 확인했다.

교정본의 공개 API 검증 20단계도 통과했다. 실행 시각과 결과는 [후속 검증 보고서](evidence/api-smoke-copy-review.json)에 기록했다. 전체 스크립트 실행 시간은 8,048ms이며 성능 벤치마크가 아니다. 이 실행에서 내려받은 증빙은 Kotlin에서도 **131행, 일치 123건, 검토 승인 8건, 감사 이벤트 17건**으로 재계산을 통과했다. 체크섬은 `444735a3ace1331a77d466c7b5ec92f00792baab229f0f282b816c7fdc56829a`이다. 최초 공개 검증 보고서는 별도로 보존했다.

README의 대시보드·거래 검토·모바일 캡처도 교정본으로 갱신했다. 이번 문구 검토에는 외부 LLM API를 사용하지 않았고, 새 API 키를 발급하지 않았다.

## P0 기능·UI/UX 개선 검증

2026-09-01, 예외 거래를 찾고 연속으로 검토하는 핵심 동선을 우선 개선한 뒤 로컬 빌드와 실제 브라우저에서 다시 검증했다.

- `npm run verify`: 레이어 경계 35개 모듈, 타입 검사, lint, TypeScript 테스트 80개, Next.js 프로덕션 빌드가 모두 통과했다.
- 대시보드: 안내 카드의 기본 동작이 `확인할 거래 보기`로 연결되고, 확인 필요 거래 목록이 차트보다 먼저 표시되는 것을 확인했다. 사이드바의 `거래 대사 8`도 확인 필요 탭으로 바로 이동한다.
- 대사 목록: 전체 거래 탭에서도 미검토 예외 8건이 먼저 정렬되며, 차액이 0원인 입금 확인 필요 거래 2건도 자동 일치 거래보다 앞에 남는다. 탭은 `tablist`·`tab`·`tabpanel` 관계를 갖고, 왼쪽·오른쪽 화살표와 Home·End 키로 선택과 포커스가 함께 이동한다.
- 연속 검토: `LM-2608045`에서 검토 예시와 원본 확인을 입력한 뒤 `기록하고 다음 거래 보기`를 실행했다. 미검토 건수가 8건에서 7건으로 줄고 대사 처리율이 94%에서 95%로 바뀌었으며, 다음 우선순위 거래 `LM-2608063`이 같은 서랍에서 열렸다. 기록 전에는 사유·증빙·원본 확인·최신 대사의 충족 여부가 각각 표시된다.
- 자료 가져오기: 1280×720 화면에서 샘플 주문 3행을 검증한 상태로 `자료 반영` 버튼의 상단 639px, 하단 675px, 화면 높이 720px을 확인했다. 긴 열 연결과 미리보기 내용은 내부에서 스크롤되고 실행 버튼은 화면에 남는다.
- 모바일 메뉴: 390×844 화면에서 문서 너비 375px과 화면의 콘텐츠 너비 375px이 같아 가로 넘침이 없었다. 메뉴가 열리면 본문에 `inert`가 적용되고 스크롤이 잠긴다. 첫 항목에서 Shift+Tab을 누르면 마지막 항목으로, 마지막 항목에서 Tab을 누르면 첫 항목으로 이동하며, Escape로 닫은 뒤 `메뉴 열기` 버튼에 포커스가 돌아왔다.
- 제품 가이드: 모바일 본문과 보조 문구의 글자 크기를 높이고 저대비 색을 교체했다. `#5b6d52`는 흰색에서 5.59:1, `#f7f8f3`에서 5.24:1이며, `#526447`은 각각 6.42:1과 6.01:1이다.
- 화면 증빙: 동일한 데모 데이터로 데스크톱 대시보드, 거래 검토 서랍, 390px 모바일 화면을 다시 캡처해 `docs/evidence`에 반영했다.

## 검증하지 않은 범위

실제 PG·은행 연동, 고객 자료, 대량·장시간 트래픽, 여러 승인자의 작업, 보안 침투 테스트, 백업 복구, Docker 실행, 회계·개인정보 관련 법적 요건 충족 여부는 검증하지 않았다. 로컬 PGlite와 CI PostgreSQL의 테스트 통과를 클라우드 운영 성능의 근거로 사용하지 않는다.
