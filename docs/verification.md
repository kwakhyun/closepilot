# 검증 현황

이 문서는 현재 코드의 검증 기준, 최근 변경의 실행 기록과 재현 방법을 담는다. 이전 개발 단계의 결과는 [검증 이력](verification-history.md)에 보존한다. 모든 수치는 합성 데이터와 검증 환경에서 얻었으며 실제 고객 성과나 운영 SLA를 뜻하지 않는다.

현재 제품 디자인은 [최신 화면 모음](screenshots.md)을 기준으로 확인한다. 아래 날짜별 실행 기록에 연결된 스크린샷은 해당 검증 시점의 화면이다. 특히 콘솔 리메이크 이전의 녹색 화면은 과거 근거로 보존하며 현재 UI를 뜻하지 않는다.

## 2026-10-22 필수 개선과 DB 초기화 수정

Node.js 24.19.0과 PGlite에서 `npm run verify`가 통과했다. 74개 모듈의 계층 검사, 타입 검사, ESLint, 24개 파일의 216개 테스트(111.84초), Next.js 16.3.8 프로덕션 빌드를 포함한다. `npm run test:coverage`도 216개 전부 통과했다(130.21초). 문장 94.77%, 분기 88.44%, 함수 97.01%, 줄 95.17%로 기존 커버리지 대상과 기준을 그대로 충족하며, 최종 verify와 커버리지 실행 모두 건너뛴 테스트는 없다.

같은 브라우저의 두 탭에서 버전이 같은 서로 다른 작업을 열면, 이전 탭의 다운로드와 설정 복제가 새 쿠키의 작업을 대상으로 실행되는 문제를 수정했다. 다운로드는 화면의 `draftScope`를 URL에 담고 복제는 확인 창을 열 때 보관한 값을 헤더에 담는다. 서버는 세션 권한과 별개로 작업 식별값을 확인하며, 누락은 400, 불일치는 409로 거부한다. 복제의 실패 경로에서 데이터, 감사, 사용량과 쿠키가 바뀌지 않는지 회귀 테스트로 검사한다.

정책 비교에서는 반올림 후 수수료와 예외 유형이 같아도 승인 지문이 바뀌면 재검토 대상으로 표시한다. 1원 주문의 요율을 330bps에서 331bps로 바꾸는 사례를 추가했으며, 원본 메모와 상태를 보존한다. Kotlin 합계는 BigInteger로 전부 더한 뒤 최종 한도를 검사하도록 맞췄다. 8,000억 원 + 5,000억 원 − 6,000억 원은 기존 TypeScript 계약대로 7,000억 원으로 허용하고, 최종 합계가 한도를 넘는 양수·음수 사례는 계속 거부한다.

기존 PGlite 테스트는 10초 `beforeAll` 안에서 새 DB 런타임까지 준비해 시간 초과가 났다. Node.js 24.19.0에서 별도로 측정한 새 메모리 DB 준비 시간은 13.121초, 빈 클러스터 스냅샷 복원은 3.934초였다. 실제 migration까지 포함한 복원은 8.438초와 6.001초로 변동했다. 빈 클러스터는 global setup에서 한 번 만들고, 각 파일의 독립 DB 복원과 migration은 `setupFiles`에서 준비하도록 분리했다. 기존 hook 10초, 테스트 30초 제한은 유지했다. schema 오류가 setup 실패로 전달되는 경로는 코드에서 확인했으며 의도적인 실패 주입은 하지 않았다. SQL과 PostgreSQL 연결 분기는 그대로다. 집중 검증은 5개 파일, 40개 테스트, 건너뜀 0개로 통과했다(120.08초). 두 DB의 쓰기 격리를 실제 쿼리로 확인했고 이 전용 회귀는 PostgreSQL CI에서만 명시적으로 제외된다.

JDK 21.0.12.1에서 Kotlin 테스트 16개를 실제 실행해 실패·오류·제외 없이 통과했다. 새 패키지는 공개 import, reconcile, resolve, close 명령으로 생성했으며 Kotlin HTTP `/reconcile`, `/verify`와 CLI에서 검증했다. CLI 결과는 129행, 일치 120건, 검토 9건, 감사 15건이고 해시는 `951b34c771d6e72b4f408c54e81b3011a50b7e35120c1074b40eef1e39d20ed3`다. `npm run fixtures` 재생성 후 기존 fixture와 migration 변경은 없었다. 기존 TypeScript 계약에 Kotlin을 맞춘 수정으로 `krw-net-v1.2.0`과 패키지 형식을 유지한다. 기본 패키지 해시 `346283a9189f0097131295ea650221edcbcf92376dfdcad3bf049f04a5c22ebd`, 정책 변경 패키지 해시 `a87f310eec4d11f1873e6b7d6f99939a531e33a433bbb31efd6afbf6be341a6b`, 구형 패키지 해시 `2402866290bef63d3b448df4864a5e749baafb31fe5394e0c0bbdb5adbe6c874`를 다시 확인했다.

사용자의 승인을 받아 npm 레지스트리에서 취약점 정보를 조회했다. Next.js와 `eslint-config-next`를 16.3.8로 올리고 호환되는 하위 의존성을 갱신했다. 운영 의존성 경고는 critical 1개와 high 3개에서 0개로 줄었다. 개발 도구까지 포함한 전체 검사는 critical 1개와 high 10개에서 high 5개가 남았다. 남은 경고는 패치가 없는 `braces` 하나와 이를 포함한 ESLint 의존성 경로다. 강제 다운그레이드나 경고 제외는 적용하지 않았다. [정확한 버전과 검사 결과](evidence/security-audit-20261022.json), [보안 모델과 남은 한계](security.md#의존성-검사)에 기록했다.

최종 `CI=1 PLAYWRIGHT_PORT=3221 PLAYWRIGHT_DATABASE_URL="" npm run test:e2e -- --retries=0 --trace=retain-on-failure`는 새 PGlite와 프로덕션 서버에서 6개 모두 통과했다(1.0분). 동일 버전의 다른 작업으로 전환한 뒤 stale 탭의 CSV 다운로드와 새 월 복제가 409로 거부되고, 현재 작업과 보관함이 그대로인지 확인했다. [1440px 안내](evidence/workspace-scope-1440-20261022.png)와 [390px 안내](evidence/workspace-scope-390-20261022.png)를 직접 확인했으며, 기존 320px과 390px 흐름의 가로 넘침 검사도 통과했다.

초기 브라우저 검사에서는 추가한 알림 선택자가 Next.js 기본 알림과 중복되어 실패했다. 선택자를 수정한 뒤 캡처에서 오류 toast가 native dialog 뒤에 가려지는 문제도 발견해, 확인 대화상자 내부에 오류를 표시하도록 보완했다. 각 화면 크기에서 실제 거부 요청 직후 안내를 검사하고 캡처하며, 다음 요청을 준비할 때 이전 오류가 사라지는지 확인한다. 중간 재실행에서는 기존 마지막 시나리오가 90초 제한에 걸렸다. 별도 HTTP 서버와 검증이 겹친 실행이었으며 그 사실만으로 원인을 단정하지 않는다. 추가 서버를 종료한 뒤 최종 실행은 동일한 테스트 제한과 사용량 조건을 유지하고 재시도 없이 통과했다.

별도 프로덕션 서버와 전용 임시 PGlite에서 [HTTP smoke 20단계](evidence/api-smoke-fixes-20261022.json)가 모두 통과했다(11.89초). 세션 생성, Origin 거부, 동시 요청, CSV 반영과 검토, 마감 불변성, scope가 포함된 CSV/JSON 내보내기와 무결성 재계산을 확인했으며 사용한 서버는 종료했다.

`npm run format:check`와 `git diff --check`도 통과했다. 수정한 설계, 보안, 검증 문서의 로컬 링크 34개에 대상 파일이 존재하는지 확인했다.

이번 검증은 합성 자료를 사용한 로컬 실행이다. SQL은 변경하지 않았으며 실제 PostgreSQL, 실제 AI 호출과 공개 배포는 이번에 다시 검사하지 않았다.

## 2026-09-05 수정 검증

Node.js 24.19.0에서 전체 `npm run verify`를 실행했다. 이 작업 전용 Colima VM의 PostgreSQL 17에서 145개 테스트와 빌드가 통과했으며, 검증 후 임시 VM과 DB를 삭제했다. 저장 전 합계 초과 거부, 상태·감사·receipt 롤백, 저장된 프로필 복제와 만료·버전 충돌, AI 생성 예약의 동시성·호출량·캐시 분리·늦은 완료를 검사했다. 런타임 마이그레이션 3으로 새 저장소를 생성한 뒤 해당 테스트를 실행했다.

이번 변경은 로컬 검증이며 아래의 기존 공개 배포 검사와 구분한다.

## 2026-09-05 화면과 조회 개선 검증

화면 상태, 차트 표현과 조회 DTO를 개선한 뒤 Node.js 24.19.0과 PGlite에서 `npm run verify`를 실행했다. 첫 실행은 AI 저장소 테스트의 DB 초기화가 10초 hook 제한에 걸렸고, 150개가 통과하고 6개는 실행되지 않았다. 제한이나 테스트 조건을 바꾸지 않고 재실행해 16개 파일의 156개 테스트와 구조 검사, 타입 검사, ESLint, 프로덕션 빌드를 통과했다. `npm run test:coverage`도 156개 모두 통과했으며 현재 표의 커버리지를 기록했다. 화면용 `trend-data.ts`의 단위 테스트는 실행하지만 위 커버리지 집계 범위에는 포함하지 않는다.

모바일 다운로드 버튼을 정리한 뒤의 PGlite 재검증에서는 두 저장소의 초기화가 시간 초과로 실패해 135개가 통과하고 21개는 실행되지 않았다. 기존 자료와 분리한 임시 PostgreSQL 16에서는 같은 제한과 조건으로 156개 테스트(11.68초), 구조 검사, 타입 검사, ESLint와 빌드를 모두 통과했다. 검증 후 임시 컨테이너를 정리했고 해당 컨테이너가 남지 않은 것을 확인했다. 모든 화면 수정이 끝난 뒤에는 PGlite의 `npm run verify`도 156개 테스트(5.18초)와 빌드까지 통과했다. 앞선 초기화 시간의 불안정성은 실행 이력으로 남겨 둔다.

최종 `CI=1 PLAYWRIGHT_PORT=3133 npm run test:e2e`는 실행별 PGlite와 별도 프로덕션 서버에서 7개가 모두 통과했다(21.4초). [320px 대시보드](evidence/overview-improved-320.png), [390px 대시보드](evidence/overview-improved-390.png), 1440px 음수 차트, [390px 음수 차트](evidence/negative-chart-390.png)를 직접 확인했다. 작은 화면의 기본 샘플 금액은 한 줄에 들어오는지 검사하며, 크기 변경 직후에는 메뉴가 화면 밖으로 이동한 것을 확인한 뒤 캡처한다. 실제 AI 호출은 끄고 기존 공급자 대역을 유지했다.

[HTTP smoke 보고서](evidence/api-smoke-presentation-20260905.json)는 개발 서버에서 20단계 통과를 기록한다(978ms). 조회 계약에 맞춰 smoke 스크립트도 수정하되, 전체 입력과 스냅샷 해시 검사는 제거하지 않고 다운로드한 패키지에 적용했다. 생성된 Playwright 보고서의 외부 JavaScript가 린트에 포함되는 문제도 발견해 `playwright-report`, `test-results`와 커버리지 산출물을 정적 검사와 포맷 검사에서 제외했다. 테스트 소스는 제외하지 않았다. `npm run format:check`와 `git diff --check`도 통과했다.

화면 조회와 패키지 다운로드는 브라우저 테스트에서 별도로 확인한다. 조회의 `close`는 `hash`, `closedAt`, `closedBy`만 포함하고, 다운로드한 패키지는 같은 해시와 전체 원본 입력 및 대사 행을 유지해야 한다. 저장 객체를 읽기 전후로 비교하는 테스트도 추가했다. 도메인 규칙, 승인 지문, SQL과 마감 패키지 형식은 바꾸지 않았으므로 규칙 버전과 Kotlin 코드는 유지했다. 이번 화면 개선에서는 Kotlin을 다시 실행하지 않았다.

128건 완료 예시의 조회 JSON은 압축 전 216,063바이트에서 115,653바이트로 46.47% 줄었다. 같은 문자열을 Node.js의 gzip으로 압축한 비교값은 21,901바이트와 12,125바이트다. 이는 로컬 직렬화 크기 비교이며 실제 네트워크 전송량, 응답 시간이나 사용자 체감 개선 측정은 아니다. [측정 조건과 결과](evidence/presentation-metrics-20260905.json)
