# 시연 순서

## 1. 기준 상태

새 데모는 2026년 8월, 주문128, 정산127, 일치120, 예외8로 시작한다. 총 매출17,072,000원, 예상 정산16,072,966원이다. 차트의 일별/채널별 전환, 표의 정렬과 필터는 실제 행을 집계한다.

첫 화면의 93.8%는 합성 입력에서 나온 비율이다. 실제 고객 자동화율이라고 설명하지 않는다.

## 2. 중복을 검토하되 숫자를 지우지 않기

`LM-2608045`를 열고 “정규화된 정산 원본 2행 보기”를 펼친다. 같은 `ST-2608045`가 두 번 있으며 예상183,312원, 실제366,624원이다.

“데모 검토 예시”로 합성 검토 사유/근거를 채우고 확인 체크 후 승인한다. 미검토는7로 줄고 검토 기록이 생기지만 원본 차액과 전체 일치 수120은 유지된다. 표의 “검토 완료”에서도 해당 거래를 다시 찾을 수 있다.

## 3. 고객 온보딩을 흉내 내기

자료 업로드 → 주문 원장 → 샘플 불러오기 → 열 매핑/3행 미리보기 → 반영한다. 새 자료 경고가 보이고 마감은 막힌다. 정산 자료도 같은 흐름으로 반영하고 대사를 실행한다. 총131건, 일치123건, 기존 예외8건이 된다.

같은 파일을 다시 반영하면 중복 내용을 거부한다. CSV 값을 잘못 바꾸면 반영 전에 오류가 표시된다. 원본 개인정보는 업로드하지 않는다.

## 4. 확정과 인수인계

처음에는 마감 점검에서 미검토 예외가 남아 확정이 불가능하다. 나머지 예외에 근거를 기록하면 체크리스트가 준비 상태로 바뀐다. 시차에는 차월 이월, 중복에는 중복 제외 검토 승인이 적용된다.

마감 확정 후 업로드/재대사가 비활성화되고 서버도 변경을 거부한다. JSON을 다운로드한다. CSV에는 승인 후에도 원본 차이가 남는다.

```bash
cd verifier
bash gradlew run --args='/absolute/path/to/closepilot-2026-08-close.json'
```

검증기는 원본 입력에서 재계산한 결과와 승인·감사 체인을 확인한다. PASS가 실제 증빙의 진위나 이체 권한을 뜻하지 않는다는 안내도 출력한다.
