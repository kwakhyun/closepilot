# 시연 순서

## 1. 기준 상태

새 데모는 2026년 8월 자료로 시작한다. 주문 128건, 정산 내역 127행을 비교하면 자동 일치 120건, 예외 거래 8건이 나온다. 주문 총액은 17,072,000원, 예상 정산액은 16,072,966원이다. 차트의 일별·채널별 전환과 표의 정렬·필터는 현재 자료를 기준으로 동작한다.

첫 화면의 자동 일치율 93.8%는 직접 만든 가상 거래에서 나온 결과다. 실제 고객의 업무 자동화율을 측정한 수치가 아니다.

## 2. 온보딩 설정 비교와 복제

**온보딩 설계**에서 LUMIÈRE와 MORROW FOODS의 채널·요율·열 연결을 비교한다. 화면의 문제 가설, 확인 질문, 적용 설정과 로드맵은 실제 인터뷰 결과가 아닌 가상 온보딩 예시다. MORROW FOODS로 새 데모를 시작하면 주문 96건과 자사몰·쿠팡 요율이 적용된다. 현재 설정에 새 가상 브랜드 이름을 입력하면 같은 설정을 복제한 독립 세션이 만들어지며, 기존 승인과 마감 결과는 바뀌지 않는다.

## 3. 중복 정산 검토

`LM-2608045`를 열고 **연결된 정산 내역 2행 보기**를 펼친다. 정산번호 `ST-2608045`가 두 번 기록되어 있으며, 예상 정산액은 183,312원, 자료상 정산액은 366,624원이다.

거래 상단의 **AI 초안 사용 가능**을 누르면 초안 영역으로 이동한다. 근거 확인·ID 검증·메모 정리 단계를 확인하고 결과의 근거 ID를 검토한 뒤 입력란에 적용한다. 또는 **검토 예시 불러오기**로 가상의 검토 사유와 증빙 참조 정보를 입력한다. 원본 자료를 확인한 뒤 체크하고 **기록하고 다음 거래 보기**를 누른다. 미검토 거래는 7건으로 줄고 다음 거래가 바로 열리지만, 원본 차액과 자동 일치 120건은 유지된다.

## 4. CSV 자료 가져오기

**자료 가져오기 → 주문 자료 → 샘플 주문 불러오기**를 누른다. 저장된 프로필 열 연결을 불러오거나 자동 연결을 확인하고 **이번 열 연결을 온보딩 프로필에 저장**을 선택한 뒤 **자료 반영**을 누른다. 새 자료 안내가 표시되며, 대사를 다시 실행하기 전에는 검토 승인과 마감 확정을 할 수 없다. 정산 샘플도 같은 순서로 반영하고 **대사 실행**을 누르면 전체 131건, 자동 일치 123건, 예외 거래 8건이 된다.

같은 파일을 다시 가져오면 중복 반영을 차단한다. CSV에 잘못된 금액이나 날짜가 있으면 저장 전에 오류를 표시한다. 실제 거래 자료나 개인정보는 업로드하지 않는다.

## 5. 확정과 인수인계

**마감 점검**에서는 미검토 거래가 남아 있으면 확정할 수 없다. 나머지 예외 거래에 검토 사유와 증빙 참조 정보를 입력하고 승인한다. 입금 확인이 필요한 거래에는 **이월 검토 승인**, 중복 정산에는 **중복 확인 승인**, 나머지에는 **차이 검토 승인**을 사용한다. 모두 검토한 뒤 최종 확인란에 체크하고 **8월 마감 확정**을 누른다.

마감을 확정하면 자료 가져오기와 대사 실행 버튼이 비활성화되고 서버도 변경 요청을 거부한다. **마감 증빙 다운로드 (JSON)**을 눌러 결과를 저장한다. CSV에도 검토 승인 전의 원본 차액이 그대로 남는다. 세션은 6시간 후 만료되므로 필요한 파일을 미리 내려받는다.

```bash
cd verifier
bash gradlew run --args='/absolute/path/to/closepilot-2026-08-close.json'
```

검증기는 원본 입력으로 다시 계산한 결과, 검토 근거, 감사 기록의 해시 연결을 확인한다. `PASS`는 이 검사에 통과했다는 뜻이며, 외부 증빙의 진위나 송금 권한을 보장하지 않는다.

로컬·CI에서는 `bash gradlew run --args='--server 8081'`로 Kotlin 서비스를 실행하고 `POST /reconcile`에 규칙 버전·프로필 요율·주문·정산 입력을 보낼 수 있다. 공개 Vercel 데모는 JVM을 실행하지 않으며 TypeScript 인프로세스 엔진을 사용한다.
