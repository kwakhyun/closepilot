# 제품 기획: 근거를 남기는 매출 마감

## 출발점과 가설

PortOne Commerce Ops 채용 설명의 “고객 업무 이해 → 문제 정의 → 구현·배포 → 재사용” 흐름을 작은 제품으로 입증한다. 실제 고객을 만났다는 증거는 없으며, 아래의 브랜드·담당자·문제는 설계 가설이다.

가상 브랜드 LUMIÈRE의 재무 담당자는 월말에 자사몰·스마트스토어·쿠팡 자료를 받아 주문별 순정산액을 비교한다. 합계가 다른 이유를 별도 문서에 남기면 다음 검토자가 숫자와 설명을 다시 연결해야 한다고 가정했다.

**핵심 질문:** 이번 달의 어떤 차이를, 어떤 근거로, 누가 확인했는가?

## 범위 결정

| 우선순위 | 고객 작업       | 완료 기준                                                                      |
| -------- | --------------- | ------------------------------------------------------------------------------ |
| P0       | 채널 CSV 온보딩 | 열을 매핑하고 오류 행을 반영 전에 발견한다. 실패하면 전체 상태가 유지된다.     |
| P0       | 주문/정산 비교  | 정수 원 단위 결과와 예외 분류를 동일 입력에서 재현한다.                        |
| P0       | 차이 검토       | 사유·증빙 ID 없이 승인할 수 없다. 승인 후에도 원본 차이가 보인다.              |
| P0       | 마감 확정       | 새 자료 재대사와 모든 예외 검토 전에는 거부한다. 확정 뒤 변경을 막는다.        |
| P0       | 인수인계        | 입력·규칙 버전·결과·승인·감사 기록을 한 파일로 내보내고 Kotlin으로 재검증한다. |
| P1       | 검토 우선순위   | 금액 차이 정렬, 채널/상태 필터, 근거 기반 검토 가이드를 제공한다.              |
| 제외     | 실제 돈과 회계  | 결제·환불·송금·분개·세금 신고를 수행하지 않는다.                               |

이 데모의 “마감”은 **검토 패키지 확정**이다. 실제 월 재무제표 확정이나 PG 지급 승인과 구분한다. 누락·중복 차이도 근거를 남겨 승인할 수 있지만, 원본 수정이나 자동 회계 조정을 하지 않는다.

## 현장 인터뷰에서 확인할 질문

1. 마감 완료의 정의와 최종 승인자는 누구인가? 마감 후 수정은 어떤 결재 절차를 거치는가?
2. 거래 ID는 채널/상점/주문/상품 단위 중 어디에서 유일한가? 분할 정산은 어떻게 식별하는가?
3. 환불 시 수수료는 언제, 어떤 기준으로 돌려받는가? VAT·프로모션·배송비는 어느 금액에 포함되는가?
4. 입금 확인의 진실 원천은 정산 파일인가, 은행 명세인가? 휴일과 월 경계는 어떻게 다루는가?
5. 어떤 예외를 차월로 넘길 수 있는가? 허용 오차와 증빙 보관 기간은 무엇인가?
6. 원본 자료의 개인정보, 접근 권한, 국외 처리, 보관·삭제 정책은 무엇인가?

## 온보딩 체크리스트

계약 수수료·반올림·매출 인식일을 먼저 문서로 합의한다. 거래 ID와 채널을 매핑하고, 정상·부분 환불·중복·누락·차월 입금 샘플을 각각 받는다. 과거 월 한 개를 병행 대사하여 고객의 수기 결과와 차이를 검토한다. 승인자를 지정하고 오류/장애 시 되돌리는 절차를 시연한 뒤 확장한다.

현재 구현의 수수료 330/385/880bps는 가상 정책이다. 실채널 요율이 아니다. 한 통화 KRW, 한 기간 2026-08, 한 가상 브랜드만 지원한다.

## 측정 계획: 아직 측정하지 않은 운영 성과

| 지표             | 정의                                               | 측정 계획                                |
| ---------------- | -------------------------------------------------- | ---------------------------------------- |
| 온보딩 소요 시간 | 입력 정책 합의부터 첫 유효 대사까지                | 고객별 작업 로그와 단계별 막힘 기록      |
| 검토 노동 시간   | 파일 확보 후 최종 승인까지 담당자의 실제 작업 시간 | 동일 월 병행 작업 비교, 대기 시간은 분리 |
| 예외 설명 완결률 | 증빙과 처리 사유를 갖춘 예외 / 전체 예외           | 승인 필드와 표본 증빙 확인               |
| 거짓 일치        | 엔진 일치 판정 중 외부 확인 결과 불일치 비율       | 은행/PG 원본과 표본 감사                 |
| 재현 가능성      | 같은 입력·규칙 버전의 결과 동일 여부               | 골든 픽스처와 Kotlin 재계산              |

128건의 샘플은 회귀 검증 자료이지 PMF, 업무 절감 효과, 실고객 정확도 증거가 아니다.

## 제품화할 자산과 다음 결정

채널별 요청은 CSV 열 어댑터와 계약 정책으로 분리하고, 금액·대사·승인 불변식은 공통 코어에 남긴다. 다음 실제 고객 검증에서 다중 상점 ID, 분할 정산, 원천 자료 버전, 결재선 중 무엇이 가장 큰 마찰인지 확인하고 우선순위를 다시 정한다.
